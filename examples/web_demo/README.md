# LingTTS 热点网页演示

独立 ESP-IDF 工程，用引擎 API（`lingtts_engine.h`），不依赖小智后台、ASR、LLM 或互联网。
连接设备热点后，在网页输入文本，设备流式合成并通过 I2S 播放；播放结束显示本次跑分。

## 硬件与默认配置

- ESP32-S3 N16R8：16 MB Flash，8 MB 八线 PSRAM，CPU 240 MHz。
- MAX98357A：BCLK GPIO15、LRCK GPIO16、DIN GPIO7，共地，按模组要求供电并连接扬声器。
- 16 kHz、16 bit、单声道；默认音量 30%。本工程不驱动 LCD。
- 引擎用 `LINGTTS_MEM_PSRAM`：模型、词典、合成器和前端工作区都在 PSRAM，64 KiB PCM 队列也在 PSRAM；任务栈、网络和 I2S DMA 仍需内部 RAM。
- 热点 `LingTTS-Demo`，密码 `lingtts-demo`；地址 `http://192.168.4.1`。
- 不自动弹出门户，也不提供互联网。手机提示“无互联网”时选择保持连接。

## 构建与烧录

在 SDK 包的根目录（GitHub Releases 里的 `lingtts-sdk-*.tar.gz` 解压后）：

```bash
. ~/esp/esp-idf-v5.5.6/export.sh
idf.py -C examples/web_demo -B build/web_demo build
idf.py -C examples/web_demo -B build/web_demo -p /dev/ttyUSB0 flash monitor
```

`flash` 会替换当前应用和分区表，并写入模型与词典。不是小智插件；烧录前确认要将板子切换为演示固件。
不运行 erase-flash，不自动擦除 NVS；但本分区布局与其他固件可能不同，恢复其他固件时需采用其正确布局。

`flash` 把 `lingtts.bin`、`lingtts_fe.bin` 写进 `lingtts_model`、`lingtts_fe` 分区：默认来自 SDK 包的 `assets/`，
也可以用 `-D LINGTTS_ASSET_DIR=/绝对路径` 指定。
词典分区 3 MB，换成完整词典（`lingtts_fe_full.bin` 改名为 `lingtts_fe.bin`）也放得下。
社区模式无需授权文件、不联网激活，也不限制合成时长。默认不会读取旧固件的 lingtts_lic 分区。
商业部署仍需另行书面授权；示例 MIT 与核心资源独立许可，见包根目录 LICENSE.md。
`idf.py -C examples/web_demo menuconfig` → LingTTS demo 可修改热点名称、密码、引脚和音量。

## 使用

1. 上电，等待串口输出 `Ready`。
2. 电脑或手机连接热点，浏览器打开 `http://192.168.4.1`。
3. 输入中文并点击播放；页面轮询状态，播放完毕显示摘要。
4. 每次最多 4096 UTF-8 字节（约 1300 个汉字），超过时明确拒绝，不截断。
5. 同时只接受一项任务，其他提交返回 HTTP 409。关闭网页不会中止已接受的播放，重新打开可看到状态和最后一次结果。

首版没有停止按钮、在线更新、语音输入或文本流追加。仅输入标点等不能产生音频的内容会报错 -101。
-100 表示音频输出失败；-6 表示显式设备凭证或音色权限不对（内部限时构建也可能表示额度用完）；其他错误码来自引擎。错误时摘要是部分结果。

## 指标定义

| 指标 | 定义 |
|---|---|
| 首段 PCM 延迟 | 设备接收并验证完整请求后，至第一次非空 PCM 回调；含任务调度，不含 HTTP 上传、播放预缓冲和扬声器延迟。不是实际首字出声延迟 |
| 合成处理耗时 | 完整前端和合成调用的墙钟时间，减去 PCM 回调时间（队列写入/阻塞、监测、主动让出 CPU）；包含回调外的任务调度影响，不是 CPU 周期测量 |
| RTF | 上述处理耗时 / 实际生成的音频时长；小于 1 表示该口径快于实时，不单独证明播放无断供 |
| 播放任务总耗时 | 请求接受到队列播放和保守 DMA 排空完成；包括预缓冲及尾部静音等待，不等于音频长度 |
| 内部堆/PSRAM 最低空闲 | 本次运行在合成回调和播放循环采样的最低值；包含整个应用、网络、HTTP 服务，不是精确瞬时峰值 |
| 内部堆采样最高已用 | 当前可分配内部堆总量减去上述最低空闲；不包含静态段等不属于堆的内存 |
| 演示固定 PSRAM 分配 | 复制到 PSRAM 的模型和词典、合成器 arena、前端 arena、PCM 队列之和，不含分配器开销及系统分配 |
| 合成器工作区 | `lingtts_engine_get_mem().tts_arena`，引擎按实际用量精确分配；已包含在上一行内，不能重复相加 |

播放任务先等待 320 ms PCM（短句合成完成则提前启动），使用 160 ms I2S DMA 环。末尾写满一环静音并等待一环时间加余量，避免关闭 I2S 时截断最后音节。合成与播放分属两核；RTF 不应与原单独 bench 数字直接等同。

## API

- `GET /`：所有 CSS/JS 内嵌，无 CDN。
- `POST /api/speak`：正文为 UTF-8 纯文本；202 已接受，409 忙，400 空白/非法 UTF-8/超长，408 请求接收失败。超时不能自动重试，先查询状态。
- `GET /api/status`：`idle/playing/done/error`、任务 ID、错误码与指标、`licensed`、`unlimited`（社区版为 true）、`eval_left_s`（社区版为 null，不能显示成剩余秒数）；运行中结果尚未完整。

## 验证状态与上板验收

2026-10-23 用 0.2.0-rc1 快速体验包自带的 `flash.py` 烧录到 ESP32-S3 N16R8 + MAX98357A，验证结果：

- 板上留有旧版的设备授权分区，社区固件照常启动，串口显示 `community (no activation, unlimited)`。
- 手机连热点打开网页，三句演示文本播放完整，无断音、尾音截断。
- 播放中网页按钮禁用，另行提交返回 409，不会打断当前播放；空白输入前后端都拒绝。

串口指标（热点开启，含前端）：

| 音频 | 首段 PCM | 合成耗时 | RTF |
|---|---|---|---|
| 9.12 s | 267 ms | 4.83 s | 0.53 |
| 19.80 s | 310 ms | 10.73 s | 0.54 |
| 19.80 s | 308 ms | 10.72 s | 0.54 |

比 hello 的 0.42 慢，可能是热点和 HTTP 任务与合成争用资源，原因未查证。首段 PCM 不等于喇叭实际出声时间。

还没做的检查：

- 电脑浏览器访问；多端同时提交。
- 连续播放 30 分钟以上，确认无重启、内存不持续下降。
- 接近长度上限的文本；独立录音确认声音连续。
