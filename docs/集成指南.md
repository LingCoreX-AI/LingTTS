# LingTTS 集成指南

本文说明把 LingTTS 加进自己的 ESP-IDF 工程需要做的全部事情。函数的细节见 `API参考.md`，内存和速度见 `资源与性能.md`。

## 1. 加入组件

把 SDK 里的 `components/lingtts` 整个目录复制到工程的 `components/` 下（或在 `project()` 之前
`set(EXTRA_COMPONENT_DIRS ".../components/lingtts")`），用到它的组件在 `idf_component_register` 里写 `PRIV_REQUIRES lingtts`。

- 只支持 `IDF_TARGET = esp32s3`，其他芯片 CMake 会直接报错。
- 库是预编译的，不受工程 sdkconfig 影响；库内部用到的 esp-nn、kissfft、micro-ecc 的符号都已隐藏，
  工程里自己再用这些库不会冲突。
- 建议 `CONFIG_ESP_DEFAULT_CPU_FREQ_MHZ_240=y`、`CONFIG_COMPILER_OPTIMIZATION_PERF=y`；
  有 PSRAM 时数据 cache 64 KB（`CONFIG_ESP32S3_DATA_CACHE_64KB=y`）比 32 KB 快约 3%。

## 2. 分区和资源文件

| 分区名 | 类型 | 子类型 | 大小 | 内容 |
|---|---|---|---|---|
| `lingtts_model` | data | 0x40 | 2 MB | `assets/lingtts.bin`（1.83 MB） |
| `lingtts_fe` | data | 0x41 | ≥ 0.6 MB（完整词典 ≥ 1.2 MB） | `assets/lingtts_fe.bin` |
| `lingtts_lic` | data | 0x42 | 4 KB | 可选设备凭证；社区模式不自动读取 |

子类型只要不和工程里其他分区冲突就行，引擎按**分区名**查找。`examples/hello/partitions.csv` 是 4 MB Flash 的排法，
`examples/web_demo/partitions.csv` 是 16 MB 的排法。

烧录：组件提供了一个 CMake 函数，在工程 `CMakeLists.txt` 的 `project()` 之后调用：

```cmake
lingtts_flash_assets("${CMAKE_CURRENT_LIST_DIR}/assets")                     # 模型和词典
lingtts_flash_assets("${CMAKE_CURRENT_LIST_DIR}/assets" "/path/license.bin") # 同时烧授权
```

之后 `idf.py flash` 会把资源写进对应分区。量产时也可以用 `esptool.py write_flash <分区偏移> <文件>` 单独写。
资源不需要每次都烧：只改应用时用 `idf.py app-flash`。

**词典选哪个**：`lingtts_fe.bin` 是裁剪版（0.54 MB），`lingtts_fe_full.bin` 是完整版（1.19 MB）。
裁剪版和完整版读音不同的句子约 0.6%，听感上约每 300 句有 1 句比完整版差。Flash 够用就用完整版
（改名为 `lingtts_fe.bin` 或在 `lingtts_flash_assets` 里指定的目录里替换），分区要相应加大。

也可以不用分区：把资源放在任何 16 字节对齐、引擎存续期间一直有效的内存里，
通过 `cfg.model`、`cfg.frontend`、`cfg.license` 传地址和大小。

## 3. 选内存配置

| | `LINGTTS_MEM_PSRAM`（默认） | `LINGTTS_MEM_INTERNAL` |
|---|---|---|
| 适用 | 有 ≥ 4 MB PSRAM | 没有 PSRAM，或 PSRAM 留给别的用途 |
| 内部 RAM | 约 1 KB | 约 150 KB（合成器和前端分时复用一块共享区） |
| PSRAM | 约 2.6 MB（模型和词典复制进 PSRAM，加工作区） | 不用 |
| 速度（边合成边播放，RTF） | 约 0.42 | 约 0.48 |

`hello` 例子的做法是开机检查 PSRAM 大小，自动选择。PSRAM 配置下加 `cfg.flags = LINGTTS_ENGINE_NO_COPY`
可以不复制资源，省 2.4 MB PSRAM，速度和 INTERNAL 配置差不多。

另外 `speak` 所在任务的栈要留约 8 KB 给 LingTTS（例子里主任务栈设成 16 KB）。

## 4. 合成和播放

`lingtts_engine_speak` 是阻塞调用：内部按标点切句，边合成边调用你的回调，每次给 160 个样本（10 ms）左右的
16 kHz 单声道 int16 PCM。回调在调用 `speak` 的任务里执行。

**播放有两种写法：**

1. **回调里直接写 I2S**（`examples/hello`）：最简单。I2S 写满会阻塞，自然实现流控。
   但回调阻塞期间合成也停着，合成下一块（320 ms 音频）时只靠 DMA 里剩下的数据撑着，
   所以 **I2S DMA 缓冲必须 ≥ 400 ms**（例如 `dma_frame_num = 480`、`dma_desc_num = 14`）。
   IDF 默认的 90 ms 不够，块与块之间会断音，听起来是轻微的“噗噗”声。
2. **回调只把 PCM 放进环形缓冲，另一个任务写 I2S**（`examples/web_demo`）：合成和播放并行，
   缓冲先攒 300 ms 左右再开始播放。适合同时还有网络、显示等任务的应用。

可以用 `i2s_channel_register_event_callback` 注册 `on_send_q_ovf` 统计断供次数，`hello` 例子里有示范。

**停止**：在任意任务调用 `lingtts_engine_stop(e)`，正在进行的 `speak` 在下一段 PCM 之前返回 `LINGTTS_STOPPED`，
之后不再回调。回调返回非 0 也能停止。停止不影响下一次 `speak`。

**线程规则**：一个引擎实例同一时间只能有一个 `speak`；`speak` 和 `set_voice` 要在同一个任务里调用。
能从别的任务调用的只有 `stop`，以及只读的查询函数（`lingtts_is_licensed`、`lingtts_eval_seconds_left`、`get_mem`）。

## 5. 社区模式与可选设备凭证

- 0.2.0 社区版默认无限时长，不需要 license.bin，也不自动读取旧的 lingtts_lic 分区。可省略该分区；现有示例保留它以兼容历史布局。
- `lingtts_eval_seconds_left()` 返回 `LINGTTS_UNLIMITED_SECONDS`（UINT32_MAX）；不能将它作为普通秒数显示。
- `lingtts_is_licensed()` 只反映设备凭证验签状态。社区模式返回 0 仍然可正常使用；该值也不判断是否拥有书面商业使用权。
- 商业范围由许可/合同约定，不必绑定芯片或启用设备计数。
- 如确需使用设备凭证，在 cfg.license/cfg.license_size 中显式传入。错误签名、设备不符或已校时情况下的过期凭证仍返回 -6，不能静默忽略。
- 显式设备凭证下，音色签名及可用音色列表校验保留。社区免费使用不赋予第三方/客户定制音色的使用权。
- 内部限时评估构建仍可保留用于回归，不属于社区包的默认行为。

## 6. 错误码

| 返回值 | 含义 | 常见原因 |
|---|---|---|
| `LINGTTS_OK` (0) | 成功 | |
| `LINGTTS_STOPPED` (1) | `speak` 被停止 | 调用了 `stop`，或回调返回非 0 |
| `LINGTTS_ERR_MODEL` (-1) | 模型或词典不对 | 分区不存在、没烧资源、文件损坏或版本不配套 |
| `LINGTTS_ERR_ARENA` (-2) | 内存不够 | INTERNAL 配置下内部 RAM 不足约 150 KB 连续空间；PSRAM 不够 |
| `LINGTTS_ERR_ARG` (-3) | 参数错 | 空指针、地址没有 16 字节对齐、`speed` ≤ 0 |
| `LINGTTS_ERR_VOICE` (-5) | 音色包不对 | 格式、CRC 或签名错，或和基础模型不配套 |
| `LINGTTS_ERR_LICENSE` (-6) | 授权 | 授权文件无效；内部限时构建的时长用完；音色不在授权里 |

## 7. 上线前检查

- 串口打印 `lingtts_engine_get_mem` 和 `heap_caps_get_largest_free_block`，确认内存余量；
- 连续播放几十句，确认断供次数为 0、内存没有持续下降；
- 用产品里真实会出现的文本（数字、金额、日期、英文名、型号）试听，读音问题记下来反馈给我们；
- 商业交付前确认书面使用范围；设备签发和量产工具仅在双方需要时使用。
