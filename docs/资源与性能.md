# 资源与性能（ESP32-S3 实测）

内存、Flash 和 hello 速度数据为 2026-10-22 板测。0.2.0-rc1 只改了授权逻辑（社区版默认不做设备凭证校验），合成路径与该次测试相同；网页演示的数据为 0.2.0-rc1 于 2026-10-23 实测，见“速度”一节末尾。

测试板：ESP32-S3 N16R8（16 MB Flash，8 MB 八线 PSRAM 80 MHz），CPU 240 MHz，ESP-IDF 5.5.6，2026-10-22。
RTF（实时率）= 合成耗时 / 音频时长，越小越快；小于 1 就能边合成边播放。

## 内存

| | PSRAM 配置 | INTERNAL 配置 |
|---|---|---|
| 内部 RAM（引擎） | 约 1 KB | 150.7 KB（合成器 11.4 KB + 前端 22.0 KB + 共享区 116.2 KB + 引擎） |
| PSRAM | 2.63 MB（复制的模型和词典 2.38 MB + 合成器 127.6 KB + 前端 123.8 KB） | 0 |
| 调用 `speak` 的任务栈 | 约 8 KB | 约 8 KB |
| 库的静态 RAM（.data + .bss） | 68 B | 68 B |

- PSRAM 配置加 `LINGTTS_ENGINE_NO_COPY` 时不复制资源，PSRAM 只用 0.25 MB，速度和 INTERNAL 配置相近。
- 用完整词典时，PSRAM 配置多复制 0.65 MB。
- 内存在 `lingtts_engine_create` 时一次分配，`speak` 期间不再分配，`destroy` 全部释放。
- 应用自己的 I2S DMA 缓冲：直接在回调里写 I2S 时需要 ≥ 400 ms，约 13 KB 内部 RAM（见集成指南第 4 节）。

## Flash

| 内容 | 大小 |
|---|---|
| 库代码和只读数据（链接进应用） | 约 189 KB（代码 96 KB + 数据 93 KB） |
| 模型 `lingtts.bin` | 1.83 MB |
| 词典 `lingtts_fe.bin`（裁剪版） | 0.54 MB |
| 词典 `lingtts_fe_full.bin`（完整版，可选） | 1.19 MB |
| 授权分区 | 4 KB |

合计：4 MB Flash 可以放下应用、模型和裁剪词典（`examples/hello/partitions.csv`）；完整词典需要 8 MB Flash。

## 速度

| | PSRAM 配置 | INTERNAL 配置 |
|---|---|---|
| 合成 RTF，边合成边播放（`hello`，含前端） | 0.42 | 0.48 |
| 合成 RTF，只合成不播放（跑分固件，27 句） | 0.38–0.40 | 0.49–0.51 |
| 首包延迟（`speak` 到第一段 PCM，常见长度的句子） | 0.27–0.32 s | 0.30–0.35 s |
| 首包延迟（100 字以上的长句） | 约 0.38 s | 约 0.44 s |
| `lingtts_engine_create` | 0.96 s（含复制 2.38 MB 资源） | 0.85 s |
| 授权校验（包含在 create 里） | 约 60 ms | 约 60 ms |
| 切换音色 | 几十微秒 | 几十微秒 |

- 网页演示（`web_demo`，0.2.0-rc1，热点开启，含前端）：RTF 0.53–0.54，首段 PCM 0.27–0.31 s（9.1–19.8 s 的三段音频）。比 hello 慢，可能是热点和 HTTP 任务与合成争用资源，原因未查证。
- 首包延迟指 `speak` 到第一段 PCM，不等于喇叭实际出声时间。
- 合成只用一个核（调用 `speak` 的任务所在的核）。另一个核可以跑网络、显示等任务。
- 前端（文本正则化、分词、注音）约 0.3 ms/字，在总耗时里不到 1%。
- `cfg.block = 16` 时首包快约 30 ms，总耗时多约 6%。
- 数据 cache 64 KB 比 32 KB 快约 3%。

## 输出

16 kHz、16 bit、单声道 PCM。每次回调约 160 个样本（10 ms）。同样的文本、同样的配置，每次输出完全相同。
